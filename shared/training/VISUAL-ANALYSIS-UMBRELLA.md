# Visual Analysis Umbrella

This regimen sits above visual/UI-specific training modules. It does not replace their domain gauntlets.

## Core loop
OBSERVE → DECOMPOSE → MEASURE → PERTURB → COMPARE → DIAGNOSE → REPAIR → RENDER → INTERACT → VERIFY → DISTILL → RETEST

## Required lenses
Every applicable visual task is examined for semantic meaning, spatial relationships, temporal behavior, interaction paths, perceptual communication, rendering quality, responsive behavior, accessibility, state fidelity, efficiency, and recovery.

## Cross-domain learning
Emulation, rendering, UI, browser verification, animation, geometry and future visual labs may contribute candidate principles. A principle is transferred only after destination-domain testing. Provenance and failed transfers are retained.

## Truth rule
A convincing visual result is evidence about presentation, not proof that the underlying operation succeeded. Likewise, a computationally correct result can still be visually poor.

## Site relevance
For the current site, favor capability density and rich manifestation without importing OS-only machinery. Movable and locked placements are constraints. Generated controls bind to semantic objects/actions rather than permanent coordinates.

## Training progression
1. Controlled deterministic fixtures.
2. Mutations and repair.
3. Responsive/spatial/temporal disruption.
4. Cross-domain candidate transfer.
5. Runtime/browser observation.
6. Human perceptual feedback when available.
7. Repeated destination validation before promotion.
